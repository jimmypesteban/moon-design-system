## Hue ramps

Each row is one hue's full ramp, step 1 (lightest) → 10 (darkest). The
brand's primary hex for that hue is always step 6 (`DEFAULT`), outlined
below.

Every hue is exactly this: ten steps and nothing else. There used to be a
`light`/`dark` pair hanging off some rows — legacy companions, hand-picked per
hue before the systematic scale existed. Measuring them retired the lot: **not
one matched any step of its own ramp exactly**, but six had no call sites at
all and five sat within 9 RGB units of a step, so those went with no visible
change. The last six were swapped deliberately, accepting shifts of 18–55 RGB
units across 317 uses, to leave one vocabulary instead of two.

So there is no `mo-yellow-dark` to reach for, and no `mo-red-light` that never
existed in the first place. **Use the ramp**: steps 1–3 where you would have
wanted `light`, 8–10 where you would have wanted `dark`. It is the same range in
steps that were actually designed, and it exists for every hue.

## Contrast ratios

Every swatch's modal shows a WCAG 2.1 **relative-luminance contrast ratio**
against white and `mo-black` text — a single number from `1:1` (identical
colors, no contrast at all) to `21:1` (pure black on pure white, the
maximum possible). It's computed from each color's relative luminance, the
same formula (and the same code) used to catch and fix `Avatar`'s level
ribbon colors via the a11y addon — not a subjective read.

WCAG defines two pass bars against that ratio:

- **AA** — the standard accessibility bar, and what this package targets:
  `4.5:1` for normal text, or `3:1` for large text (18pt+, or 14pt+ bold)
  and UI components like icons/borders.
- **AAA** — the stricter, enhanced bar: `7:1` for normal text, `4.5:1` for
  large text. Not required, but worth reaching for critical text.

This is the classic WCAG 2.1 ratio, not the newer APCA/`Lc` metric some
tools (including Radix Colors' own modal) show instead — the two use
different math and aren't directly comparable, but WCAG 2.1 is still the
bar actually required for compliance today.

export const hueHex = (name) => {
  const parts = name.split('-');
  const base = colors[parts.slice(0, 2).join('-')];
  if (typeof base === 'string') return base;
  return parts[2] ? base[parts[2]] : base.DEFAULT;
};

export const PairCard = ({ bg, fg, tone }) => {
  const bgHex = hueHex(bg);
  const fgHex = hueHex(fg);
  const r = contrastRatio(bgHex, fgHex);
  const aa = r >= 4.5;
  const aaLarge = r >= 3;

    <div style={{ border: '1px solid #DEDCD8', borderRadius: 8, overflow: 'hidden', fontFamily: BODY_FONT }}>
      <div style={{ background: bgHex, color: fgHex, padding: '14px 12px' }}>
        <div style={{ fontSize: 15, fontWeight: 600, lineHeight: 1.3 }}>Readable body text</div>
        <div style={{ fontSize: 11, marginTop: 3, opacity: 0.95 }}>Smaller supporting line</div>
      </div>
      <div style={{ padding: '7px 10px', background: '#fff', fontSize: 11, color: '#6B6A66' }}>
        <div style={{ fontFamily: 'monospace', fontSize: 10.5, color: '#313030' }}>
          bg-{bg} / text-{fg}
        </div>
        <div style={{ marginTop: 4, display: 'flex', alignItems: 'center', gap: 6, flexWrap: 'wrap' }}>
          <strong style={{ color: aa ? '#1B4B35' : '#B82431', fontVariantNumeric: 'tabular-nums' }}>
            {r.toFixed(2)}:1
          </strong>
          <span style={{ color: aa ? '#1B4B35' : '#93928F' }}>{aa ? 'AA text' : 'fails AA text'}</span>
          <span style={{ color: aaLarge ? '#6B6A66' : '#B82431' }}>{aaLarge ? '· AA large ok' : '· fails AA large'}</span>
        </div>
      </div>
    </div>
  );
};

whether text on them is **readable**. Those are different questions, and for
the secondary palette they disagree — so the guidance below is grouped by what
each pairing is actually safe to do, with every ratio computed live from
`tokens.mjs` by the same function the swatch modals use.

### Check any pairing

The groups above cover the pairings worth naming. For anything else — a tint
you are considering, a step you are unsure about — pick the two colours and
read the number. When a pair fails, it offers the nearest step **in the same
hue** that passes, so the fix keeps the colour you wanted.

### The rule in one line

Brand pairs decide **which hues touch**; the ramp decides **whether text is
readable on them**. If a person must read it, either use a primary pairing or
put step-8/9 text on a step-1 tint — never two step-6 brand hexes.

## Usage

- **Primary actions / danger states**: `mo-red` (step 6)
- **Body text**: `mo-black`
- **Page background**: `mo-white`
- **Secondary accents**: `mo-yellow`, `mo-orange`, `mo-pink`, `mo-purple`, `mo-green`, `mo-forest`, `mo-blue`, `mo-ocean` — each paired only with its designated partner. Use steps 1-5 for light tints/backgrounds, 7-10 for darker text/emphasis, instead of the old separate `-dark`/`-light` tokens.
- **Neutrals**: `mo-grey` ramp
